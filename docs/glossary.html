Glossary

The words somm uses, in alphabetical order. Where a term names a part of somm, the link goes to that part on the components page.

abstain
What a decision call does when no label reaches the min_p you set: it still returns the probabilities but sets abstained, so your code can escalate, typically to an LLM call under the same workload.
attempt
One try at a piece of work: one request to one model, or one run of a coding agent through a harness. A call that falls back across providers makes several attempts. A harness attempt is recorded, with record=True, as its own ledger row beside API calls.
calibration
How well a decision model's probabilities match how often it is right: of the answers it gave with probability 0.9, about nine in ten should be correct. somm_core.read.decision_calibration measures it against your verdicts (Brier score and expected calibration error).
call
One request your code makes through somm, such as one generate(). Every call writes exactly one row to the ledger, including calls that fail or are refused.
chip
A small, tested, deterministic component that can do part of a workload's job instead of a model. The first kind of handler that is not a model; published by fab, not by somm.
climb
Moving the parts of a workload that a rule can decide out of the model, one step at a time, on recorded evidence, and moving them back if a model does better. Handlers and the climb.
cooldown
A timed rest for a provider and model after it fails. Stored in SQLite so every process sees it. It doubles every ten consecutive failures, to at most a day; one success clears it.
cost of pass
Dollars per correct answer: a model's cost divided by how often its graded answers pass. The number a routing decision turns on. Since 0.24.0 switch_model evidence records it for each model compared; somm frontier does not rank by it yet (ROADMAP.md, phase 5).
data boundary
How far a workload's data may travel, as one of four tiers, strictest first. A route looser than the boundary is refused before any request leaves the process. Data boundary.
  • local: the data never leaves hardware you run (Ollama or another server on loopback or a private address).
  • zdr: a third party processes it under an explicit zero-retention, no-training commitment. Only you can declare it, except where OpenRouter's published zero-retention list names qualifying upstreams for a model; the request is then pinned to those upstreams.
  • subscribed: a US-headquartered, first-party provider you hold an account with, under its standard terms (for example the Anthropic or OpenAI API). Seats are assumed to be here.
  • unvetted: everything else, including anything somm cannot classify. The default boundary, which admits every route.
decision
A recorded model choice: the question, the candidates, the model chosen and the reason. Always stored in the machine-wide mirror, so every project can find it. Not the same as a decision call.
decision call
A call to a decision model through llm.decide() or decide_many(): a typed question about some text, answered with a label and a probability for every label instead of text. Recorded as a ledger row with kind = 'decide'. Decision calls.
fallback
Moving to the next provider when a call that did not name one fails. A pinned call does not fall back unless you pass allow_fallback=True.
frontier
For one workload, the graded models ranked by score and latency (somm frontier).
gold model
The stronger model that shadow evaluation treats as the reference answer.
handler (workload handler)
A plug-in that serves a workload with something other than the provider chain: a rule, a classifier, a chip. It answers or declines; a declined call goes to the models. Each handler has a kind. A handler may declare the local tier; any other is treated as unvetted.
harness
The program that runs an autonomous coding agent: Claude Code, Codex, OpenCode or Pi. somm runs one attempt and normalises the result; it does not queue or retry. Harnesses.
inbox
Where recommendations wait for you to apply or dismiss them: somm inbox, or the MCP tools.
judge
A model, or a panel of models, that scores an answer against a written rubric. Its requests are ledger rows like any other.
kind
What serves a workload. The default kind is llm, the provider chain; a handler adds another. Separately, a ledger row's kind column marks a decision call as decide; it is empty for an ordinary call.
ledger
The SQLite file that holds one row per call for a project, at .somm/calls.sqlite. You own it and can query it with plain SQL. Ledger and mirror.
loop (intelligence loop)
Three workers that read the ledger and write back: model intel (daily), shadow evaluation (each pass) and recommendations (weekly). Run once with somm loop run or on a timer with somm loop install. A recommendation needs enough grades and a significant difference, and expires after 30 days.
MCP
Model Context Protocol, the standard way a coding agent calls outside tools. somm-mcp gives an agent 14 tools over the ledger and the sommelier. MCP server and skill.
mirror
The machine-wide copy at ~/.somm/global.sqlite. It holds calls and workloads from every project (on by default) and all decisions. It does not hold samples, evaluations or recommendations.
mirror sync
somm mirror sync: copy the call rows a registered project ledger has and the mirror lacks, in batches; safe to rerun. somm ledgers shows how far behind the mirror is.
model intel
somm's local catalogue of models, prices, context windows and capabilities. It starts from a bundled price snapshot and refreshes daily from models.dev, OpenRouter's catalogue and your local Ollama. It is a cache: answering never waits on the network.
observed ceiling
A quota limit inferred from your own rate-limit errors: the usage in the window at the moment the provider said no.
pacing
Comparing how much of a quota is used with how much of its window has passed, and trying a provider that is ahead of pace only after the others.
pin
Naming a provider or model on a call. A pin is exact: that model serves the call or the call fails, and the failure is recorded against the model you asked for.
plan
How a provider bills, declared in ~/.somm/plans.toml. PAYG (pay as you go) charges per token in dollars. Metered gives a quota per window, such as requests per five hours, where the scarce thing is headroom, not money. Plans and quota pacing.
policy
A workload's routing rules: retries, timeout, a fallback chain, or the somm/auto tiers that send simple requests to a fast model and harder ones to a stronger one.
privacy class
A per-workload label. private means the local boundary, and its calls are never sampled for grading.
project
The name a client registers under, somm.llm(project="my_app"). One project, one ledger.
provider
A place a call can go: an API such as Anthropic or OpenRouter, a local server such as Ollama, or a seat.
recall
A recorded decision that cites an earlier one, through recalled_from, and chooses the same provider and model. The count of recalls across projects is somm's north-star number. Stored since 0.23.0 and counted by somm doctor; there is no history yet.
receipt
A line another tool writes about work it did, which somm reads but does not own: chipsocket's per-decision receipts for somm climb, gipper's rental receipts for somm gpu spend.
recommendation
A proposal written by a rule, with the evidence it came from: switch model, a cheaper new model, a provider that keeps failing, or a larger output budget. Recommendations and the inbox.
route
One concrete destination for a request: a provider, a model and an endpoint. A tier belongs to a route, not a provider: the same Ollama daemon is local for a model on your machine and unvetted for a cloud-tagged one.
route source
What chose a call's route, recorded on every row: recommendation, policy (a workload policy), learned_override, pin (the caller named it) or default (the provider order). The share decided by evidence rather than a pin or the default is one of the three north-star numbers.
rung
One step of a climb: what answered a decision, such as a rule, a cache, a baseline or a model. somm climb counts decisions per rung.
sample
A stored prompt and response, with the request parameters sent (system prompt, tools, response format, temperature, max_tokens). Off by default, opted into per workload, never for private workloads. Samples are what shadow evaluation grades.
seat
A logged-in subscription used as a provider: the claude or codex command-line tools, or a ChatGPT account. Paid per month, limited per window. Seats never join the default chain; you reach them by pinning.
shadow evaluation
Re-running a sample of real calls on a gold model in the background and scoring how close the production answer was. Shadow evaluation and judges.
skill
Written instructions a coding agent loads. somm-skill teaches it to use somm.llm(), name its workloads and consult the sommelier.
sommelier
The part of somm that ranks candidate models and remembers which you chose and why, across projects. The sommelier.
stream event
One typed item from stream(events=True): StreamStart (call id, provider, model), then TextDelta, ToolCallDelta and ReasoningDelta as they arrive, and a final StreamDone carrying the recorded result.
unknown cost
A call somm has no price for, such as a self-hosted endpoint or an unlisted model. It is stored as cost_usd = 0.0 with cost_source = "unknown:no-price", and averages, comparisons and budget caps leave it out instead of counting it as free.
verdict
The right answer to a decision call, recorded once you know it with result.verdict(label). Verdicts are the labels calibration is measured against.
workload
A named job your code asks for, such as claim_extract, not a model. Cost, failures, budgets, boundaries, grades and recommendations attach to workloads. Workloads.
